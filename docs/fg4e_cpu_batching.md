# FG-4e — CPU 批量路径进库 + 实测加速比

**一句话结论：FG-4d 的 5.85–7.20× 从外推变成了实测，量级正确。** 在生产真实工作点
N=230、B=68 上，min 样本口径实测 **6.42× / 7.43×**（两次独立运行），落在 FG-4d 外推带内；
中位样本口径实测 **5.30× / 5.71×**，落在外推带下沿或略低。逐候选数值等价最差 **5.34e-15**
（预算 1e-12，未放宽）。默认路径与 `off` 冻结点逐位不动。

本 WP 只改 `network-nlo-eval`。批量是**新增入口**，`ode_accel` 三档、`evaluate_path`
编排逻辑一字未改。**没有**接 `multiband-optical-rl`（那是下一个 WP），因此**没有**
端到端 rollout 的加速比——见 §6。

所有数字来自 `results/fg4e_speedup_ab.json` 与 `results/fg4e_speedup_ab_run2.json`
两次独立运行；复算命令见 §7。

## 1. 形态：三次 GEMM，不是 (B,N,N)

朴素批量化会物化 `(B,N,N)`：N=230、B=256 就是 129 MB，N=2100、B=1024 是 36 GB。
但对扰动轴 `l` 的求和在把数据相关比值提出来后是**线性**的（FG-4c 已验证的代数）：

```
u0[b,l] = P[b,l]^2 * T[b,l]^2 / rs[l]        T = 1 + t_tilde
u1[b,l] = u0[b,l] * r[b,l]                   r = -t_tilde / T
u2[b,l] = u0[b,l] * r[b,l]^2

sigma_xpm[b,i] = (32/27) * P[b,i] * sum_l ( M0[i,l]*u0[b,l]
                                          + 2*M1[i,l]*u1[b,l]
                                          +   M2[i,l]*u2[b,l] )
M0 = gamma_sq*w0,  M1 = gamma_sq*w1,  M2 = gamma_sq*w2   （对角置零）
```

ODE 侧则是 20 步 RK4 × 4 次子步 × 2 次 GEMM（增益 + 损耗）：

```
gain = P @ g_gain.T        # (B,N) @ (N,N) -> (B,N)
loss = P @ g_loss.T
dp   = (gain - loss - alpha) * P        alpha 广播到通道轴
```

热路径**无数据相关控制流**。工作内存 O(B·N) + O(N²)：三张 (N,N) 矩阵
（`g_gain`、`g_loss`、`M0/M1/M2`）**不按 batch 复制**，一次构建、整批复用。

落到库里是：

| 文件 | 角色 |
| --- | --- |
| `src/network_nlo_eval/models/batch_kernels.py` | 批量核：`build_batch_constants` / `batched_span_noise_and_power` / `worst_relative_deviation` |
| `src/network_nlo_eval/models/isrs_gn.py` | 新入口 `calc_span_noise_and_power_batch` + 常量包记忆化 `batch_cache_stats()` |
| `tests/test_fg4e_cpu_batching.py` | 16 条等价性/不变性测试 |
| `scripts/fg4e_speedup_ab.py` | 同进程交错 A/B，产出两个 JSON |

### 1.1 广播纪律（本项目已经栽过一次的地方）

FG-4b 的 XPM pre-factor 里 `p_i` 曾经隐式广播到最后一轴、于是静默算成了 `p_l`——
它在**满载栅格上完全不可见**（`p_i == p_l`），只在拉曼倾斜让逐信道功率不再相同时才暴露。
批量核有两处同类的坑，都显式写死：

1. **`T**2` 留在扰动轴 `l`**：串行张量化核是 `pre = ((32/27)*pre) * (big_t*big_t)`，
   即 (N,N) 乘 (N,)，默认广播到**最后一维 l**。折到 `i` 轴外面是静默 2× 误差。
   本实现把它折在 `u0[b,l]` 上（`batch_kernels.py` 的 `_nli_batched`）。
2. **零功率掩码无 `continue` 可依赖**：串行逐对 `continue` 在批量下换成三条代数掩码——
   `i == l` 由 M* 对角置零（构建期）、`p_l == 0` 由 `p_sq[b,l] == 0` 使 `u* == 0`、
   `p_i == 0` 由末行 `np.where(P > 0, ...)`。三条在 §2 的部分占空与惰性通道测试里逐条把关。

`log` / `1/x` 类项（`t_tilde` 的 `p_lin_out` 除法、ASE 的 `P / p_out`）都先掩码再相除，
惰性通道不会把 nan/inf 带出核外；`test_batch_outputs_are_finite_and_shaped` 断言了
「死通道的三个噪声通道恒为 0」与「无任何非有限值」。

## 2. 等价性证据（F4e-1）

预算 **1e-12**，沿用 FG-4a 常量，**未放宽**。比较对象是**串行路径的同一候选**
（`ode_accel="matvec"`，即默认档）。

| 场景 | 最差相对偏差 | 出现位置 |
| --- | --- | --- |
| 均匀栅格 B∈{1,4,16,68,256} | **5.343e-15** | XPM，B=256 |
| 部分占空（含惰性通道 + 两端空槽）B∈{1,4,16,68} | 4.831e-15 | XPM，B=68 |
| 灵活栅格（逐连接符号率 + 64QAM `phi_kurtosis=-0.619`） | 3.197e-15 | XPM |
| n_span∈{1,2,5} × 跨长∈{100 km, 75 km} | 3.090e-15 | XPM |
| EDFA 标量 NF 覆盖 | 2.643e-15 | XPM |

逐通道（A/B 两个 JSON 的 `numeric_check`）：

| B | p_out | spm | xpm | ase |
| --- | --- | --- | --- | --- |
| 1 / 4 | 1.03e-15 | 1.06e-15 | **2.64e-15** | 1.10e-15 |
| 16 | 1.32e-15 | 1.26e-15 | **5.04e-15** | 1.52e-15 |
| 68 | 1.26e-15 | 1.30e-15 | **4.83e-15** | 1.41e-15 |
| 256 | 1.32e-15 | 1.52e-15 | **5.34e-15** | 1.52e-15 |

**XPM 是最差的一项**，与预期一致：它是唯一把 `l` 方向的成对求和换成 GEMM 累加的输出，
也是唯一 O(N²) 的项。其余三项的重排更温和。

**逐位相等没有达成**（最差 5.34e-15 ≠ 0），符合 FG-4a 以来「默认档允许末位重排」的契约。
偏差比预算小 **187 倍**。

一处**结构性假设**（诚实标注，不是偏差）：串行在**逐项**上 `np.maximum(pre*xpm_sum, 0)`，
批量在**求和之后**取 `maximum`。二者仅当各项非负时等价。默认 `phi_kurtosis=0` 时
`num2 = 0` ⇒ `w_k > 0` ⇒ 各项非负，故确实等价；64QAM 下 `n_span=1` 时 `n_tilde=0` ⇒
同样非负（§2 的灵活栅格用例正是这条路径，且偏差 3.20e-15 在预算内）。若将来出现
`phi_kurtosis ≠ 0` **且** `n_span > 1` 的组合，逐项截断与求和后截断可能分道，此时需要
重新取证——**本刀未测该组合**（§6）。

## 4. 实测曲线（F4e-2）

口径：**同进程交错** serial↔batch，每轮翻转顺序，取 **min 样本**（FG-4a/FG-4b 口径）；
两臂都是**库内路径**（serial = `_calc_span_noise_and_power`，batch = `calc_span_noise_and_power_batch`），
测的是**完整单跨段核**（RK4/SRS ODE + 张量化 NLI + ASE），不是孤立 GEMM。

线程按 FG-4c 已定的纪律钉死 `OMP_NUM_THREADS=OPENBLAS_NUM_THREADS=MKL_NUM_THREADS=8`
（本机 20 核；FG-4c 曾因 BLAS 线程超订作废过两轮扫描）。
负载 `loadavg` 在两次运行期间为 **0.92–1.33**（比该机常见的 5–45 低很多，
因此这两轮的**绝对值**可能偏乐观；但两臂同刻交错，比值不受影响）。

N=230，50 GHz 栅格，100 km 跨段，`phi_kurtosis=0`。批量形态对齐 FG-4d 观察到的真实调用：
**同一基线占用谱 + 每个候选抬高一个信道**，每 7 个信道空一个（零功率守卫在测得的路径上）。

### 4.1 加速比（min 样本口径，两次独立运行）

| B | run1 min | run2 min | run1 中位 | run2 中位 | serial µs/候选 | batch µs/候选 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **0.588×** | **0.629×** | 0.561× | 0.531× | 1119.9 / 1184.6 | 1904.0 / 1882.5 |
| 4 | 1.985× | 2.103× | 1.817× | 1.631× | 1112.5 / 1174.6 | 560.6 / 558.5 |
| 16 | 5.163× | 3.944× | 3.931× | 3.564× | 1078.3 / 1133.5 | 208.8 / 287.4 |
| **68** | **6.421×** | **7.427×** | 5.295× | 5.708× | 1064.0 / 1107.6 | 165.7 / 149.1 |
| 256 | 8.461× | 7.592× | 5.998× | 6.453× | 934.6 / 986.1 | 110.5 / 129.9 |

### 4.2 口径纪律：为什么 min 与中位差这么多

两臂的样本离散度差别很大：

| B | serial spread | batch spread（run1 / run2） |
| --- | --- | --- |
| 1 | 1.20× / 1.66× | 1.17× / 1.65× |
| 16 | 1.10× / 1.13× | **1.87× / 1.31×** |
| 68 | 1.06× / 1.11× | **1.54× / 1.60×** |
| 256 | 1.05× / 1.09× | **1.66× / 1.38×** |

批量臂的单次样本（B=68 约 10–11 ms）比串行臂（72–75 ms）短一个量级，因此对调度抖动更敏感，
max/min 能到 1.9×。**min 样本口径（本项目沿用）系统性地偏乐观**；中位口径是更保守的读数。
两个都给，是因为只报 min 就是挑对自己有利的那个统计量。

**测量可信度的正面判据**：serial 的「每候选耗时」在全部 B 上持平
（934.6–1184.6 µs），这正是「测到了工作量本身而不是测到了机器忙闲」的判据
（FG-4c 用它否掉了两轮线程超订的废数据）。本轮通过。

### 4.3 拐点

B=1 批量是**输的**（0.588× / 0.629×），B=4 已经**赢**（1.985× / 2.103×）。
拐点在 **B=2 或 B=3 附近**——本刀**没有**更细地扫（只跑了 brief 指定的五个档位），
所以真实拐点位置**未测**，只能说它夹在 (1, 4] 开区间内。与 FG-4c 在 N=230 上的
「CPU 批量拐点 B≥4」**方向一致**。

## 5. 实收 vs 外推：差在哪（F4e-2 的核心）

| | FG-4d 外推 | FG-4e 实测（min） | FG-4e 实测（中位） |
| --- | --- | --- | --- |
| B=68 加速比 | **5.85–7.20×** | **6.42× / 7.43×** | **5.30× / 5.71×** |

- **量级正确**。min 口径两点都落在外推带内；中位口径两点落在带下沿（5.30×）到带内（5.71×）。
- **外推是保守的**（两次 min 口径都 ≥ 5.85× 下界），但**没有出现"实测远超外推"的好消息**：
  中位口径甚至略低于下界。FG-4d 当初标 5.85× 为「保守下界」是对的。
- **相对已兑现的 4.678×**：B=68 实测 min 6.42–7.43× 是它的 1.37–1.59×。
- B=256 处加速比**没有继续单调上升**（run1 8.461×、run2 7.592×，而 B=68 是 6.421/7.427），
  逐候选耗时从 165.7/149.1 µs 降到 110.5/129.9 µs，但比例读数受两臂离散度支配，
  两次运行甚至互有高低（run1 B=256 最高，run2 B=68 最高）。**不宣称 B=256 优于 B=68**。

## 6. 未测 / 未验证（诚实清单）

- **未接 `multiband-optical-rl`**：批量入口目前**没有任何生产调用方**。
  端到端 rollout 的加速比**未测**——本刀测的是单跨段核的候选批，不是整条 RL 步。
  这是下一个 WP 的事。
- **只测了 N=230**（FG-4d 判定的生产 N）。N=900 / 2100 的批量曲线**未测**；
  FG-4d 已裁定 N≥900 在当前形态下达不到，故未跑。
- **只测了单跨段核**。`evaluate_path` 的多跨段累积、ROADM 阻塞、跨段噪声转移
  **未做批量**、也**未测**其加速比（批量维目前只在单跨段内）。
- **`phi_kurtosis ≠ 0` 且 `n_span > 1` 的组合未测**（见 §2 末尾的结构性假设）。
- **拐点未细扫**：只在 {1,4,16,68,256} 上测，1 与 4 之间的真实拐点位置未测。
- **run 间离散度不小**：B=68 的 min 口径两次为 6.42× / 7.43×（相差 15%），
  B=16 两次为 5.16× / 3.94×（相差 31%）。只跑了两次，没有做重复性统计检验。
- **未钉核、未隔离 CPU 频率/缓存状态**；只钉了 BLAS 线程数。两次运行 `loadavg`
  恰好落在 0.92–1.33 的低位（低于该机常见的 5–45），**绝对值偏乐观**的风险存在；
  比值因同刻交错而稳健。
- **未做 GPU 对照**：FG-4d 已裁定不做 GPU，本刀遵旨。
- **`tabular` 拉曼谱档未涉及**（FG-U1 的独立线）。
- 批量入口对 **ROADM** 的处理已实现并与串行同式，但**没有单独的测试或计时**覆盖它。
