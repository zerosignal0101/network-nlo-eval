# FG-U1：宽波段拉曼增益谱（保真线第一刀）

**分支** `wp/fg-uwb-fid`（从 `15b3c2c` 切出）　**产物** `results/fg_u1_raman.json`
**默认档未变**：既有调用方一行不改仍走 `legacy` 折线，FG-4a 金标准 31/31 逐位不变。

---

## 0. 这一刀解决什么

`numba_kernels._build_g_matrix` / `_build_g_pair_matrices` / `_calc_exact_power_profile_ode`
里的拉曼耦合是一条**合成折线**：

| 区间 | 折线 |
| --- | --- |
| `df ≤ 13.2 THz` | `g = cr * df`（线性爬升） |
| `13.2 < df < 15.6 THz` | `g = cr*13.2e12 * (15.6-df)/2.4`（线性跌到零） |
| `df ≥ 15.6 THz` | `g = 0`（**恒零**） |

对 C+L（跨度 11.45 THz）尚可，对 S+C+L+U（跨度 27 THz）有两个硬伤：

1. **`>15.6 THz` 恒零**：相隔超过 15.6 THz 的信道对之间拉曼耦合被人为置零。
   真实熔融石英谱在 20–30 THz **小而非零**。
2. **13.2 THz 附近是宽峰**（带肩部），线性爬升把峰形抹平了。

> **材料更正**：brief 写的是"硅拉曼谱"。本模型的光纤参数
> （`n2=2.6e-20`、`A_eff=80 µm²`、`D=17 ps/(nm·km)`、`α=0.2 dB/km @1550nm`，
> 见 `FiberSpanConfig` 默认值）是标准单模**石英**光纤，所以谱源取**熔融石英**，
> 不是晶体硅——两者的拉曼谱形完全不同（硅是 520 cm⁻¹ ≈ 15.6 THz 的单窄峰）。
> 本刀按石英取谱。

## 1. 谱源：有出处、可复现（FU1-2）

谱形**不是**从图上 digitization 的散点，而是从**已发表且参数完整**的响应函数**解析**得到：

**响应函数** — Q. Lin and G. P. Agrawal, *"Raman response function for silica fibers"*,
Optics Letters **31**(19), 3086 (2006), [doi:10.1364/JOSAB.6.001159](https://doi.org/10.1364/JOSAB.6.001159)：

```
h_R(t) = (tau1² + tau2²) / (tau1·tau2²) · exp(-t/tau2) · sin(t/tau1)
tau1 = 12.2 fs,  tau2 = 32 fs        （石英的拟合参数）
```

**从响应函数到功率增益谱** — 功率增益系数正比于响应函数傅里叶变换的虚部
（G. P. Agrawal, *Nonlinear Fiber Optics*, Eq. (2.3.42)；
D. Hollenbeck and C. D. Cantrell, *"Multiple-vibrational-mode model for fiber-optic Raman gain
spectrum and response function"*, J. Opt. Soc. Am. B **19**(12), 2886 (2002), Eq. (7)，
[doi:10.1364/JOSAB.19.002886](https://doi.org/10.1364/JOSAB.19.002886)）：

```
g_R(w) ∝ Im{ h̃_R(w) },   h̃_R(w) = ∫₀^∞ h_R(t)·exp(-i w t) dt
```

对上式做这个变换（令 `b = 1/tau1`、`g = 1/tau2`、`w` 为**角频率**）可**解析化简**：

```
-Im{ h̃_R(w) } = 2·b·g·w / ( (b² + g² - w²)² + (2·g·w)² )
```

这个闭式就是 `tabular` 档的谱源（`physics/raman_spectrum.py::raman_gain_spectrum_closed_form`）。

**两项交叉验证**（都由测试守着，不是口头保证）：

| 检查 | 结果 |
| --- | --- |
| 闭式 vs 对 `h_R(t)` 的**直接数值傅里叶变换** | 形状最大偏差 `1.5e-9` |
| 闭式峰位 vs 文献常引的 13.2 THz | **13.0775 THz**（差 0.12 THz，见下） |

**关于 13.0775 THz**：文献普遍引 13.2 THz，本谱给 13.0775 THz。差值来自
`tau1=12.2 fs`、`tau2=32 fs` 是**四位有效数字**的拟合参数——把 `tau1` 调约 1%
即可把峰位推到 13.2。这里**没有**去凑这个数：参数照抄文献，峰位照实报。
两者的差（0.9%）在本刀的验收口径（dB 级影响）下不重要，但**如实记录**。

### 数据表（提交进仓库）

`references/raman_gain_silica_lin_agrawal_2006.csv`，**801 行**，覆盖 `0 ~ 40 THz`，
步长 `0.05 THz`。表头带着全部出处元数据（`tau1`、`tau2`、文献 DOI、闭式）。

* **有效范围**：0–40 THz。S+C+L+U 的最大跨度 27 THz，落在表内，留了余量。
* **采样密度**：0.05 THz = 50 GHz；在 50 GHz 信道间隔的系统里，任意信道对的频差都落在栅格上或栅格中间，插值误差被 §3 的容差覆盖。
* **刻意从磁盘读**（`load_raman_gain_table()`）而不是在代码里现算：这样"用了哪条曲线"是**可 diff、可被第三方独立复核**的一件事。
* 表由 `write_spectrum_csv()` 生成，测试证明它与闭式**逐点一致**（`atol=1e-15`）——表不是手工填的数。

**超出表范围的截断**：`df > 40 THz` 显式置 0（不外推）。被截掉的尾巴在 40 THz 处只剩峰值的
**2.51%**，且 Lorentzian 尾巴本就趋于 0。

## 2. 单位与归一化：两档如何对应（一致性问题）

`cr_w_m_hz` 的既有语义是"**斜率**"，使 `G(13.2 THz) = cr * 13.2e12`。为了让两档
**只差谱形、不差幅度**（否则 legacy/tabular 的比较会被幅度混淆），`tabular` 用同一锚点归一：

```
legacy : G(df) = cr_w_m_hz · (df × 1e12)
tabular: G(df) = cr_w_m_hz · 13.2e12 · S(df)        其中 S(13.2 THz) ≡ 1
```

* `cr_w_m_hz` 在两档中的**单位与含义完全相同**（1/(W·m·Hz) 的斜率）；
* `S` 是**无量纲**形状函数，`G` 是有量纲的耦合系数——职责分开；
* 两档在 13.2 THz 处**逐位相等**（`results/fg_u1_raman.json` → `anchor_equivalence`）：

| df | legacy G | tabular G | 逐位相等 |
| --- | --- | --- | --- |
| **13.20 THz** | 3.696000e-04 | 3.696000e-04 | ✅ |
| 2.00 THz | 5.600000e-05 | 2.685221e-05 | ❌（按设计应不同） |
| 0.50 THz | 1.400000e-05 | 6.522764e-06 | ❌（按设计应不同） |
| 27.00 THz | **0.000000e+00** | **3.737596e-05** | ❌（legacy 人为置零） |

> **一处既有约定，本刀不动**：`cr_w_m_hz` 标注的单位 `1/(W·m·Hz)` 与文献里 `g_R` 的
> `m/W`（每单位*频率*）之间其实差一个长度量纲。这是 legacy 档沿用下来的既有约定，
> 改动会破坏 FG-4a 金标准。本模块只保证 `tabular` 与 `legacy` 在**同一个约定**下
> 语义一致，不去改这个约定本身。**已记录，未修**。

## 5. 接入方式（热路径不变）

```
MultiBandISRSGN(..., raman_spectrum="legacy" | "tabular")
    │
    ├── ode_accel="cached_g" → raman_g_matrix{,_tabular}(f, cr)      → 完整 G
    ├── ode_accel="matvec"   → raman_g_pair_matrices{,_tabular}(f, cr) → (g_gain, g_loss)
    └── ode_accel="off"      → 冻结路径，**拒绝** tabular（见下）
```

* **插值只发生在构建期**：`_build_g_*_matrices_tabular` 里，每个 evaluator 一次，
  且结果按频率栅格值键记忆化（`_G_CACHE`）。热路径 `_calc_dp_dz_matvec` 与
  `_calc_exact_power_profile_ode_matvec` **未被触碰**。
* **缓存键加了谱档标签**（`_g_cache_key(..., spectrum)`），两档各占各的条目。
  这是**纯增键**：legacy 条目的键变长了，但算出的 G 一位都没变。
* **`tabular` + `ode_accel="off"` 显式报错**：`off` 是 FG-2 冻结的参考路径，
  它在核内逐对重建 legacy 折线，结构上换不了谱。宁可报错，不静默退化。

### 顺带修掉的一个既有缺陷（非本刀引入）

`raman_g_matrix` 的缓存判据是 `if cached is not None: return cached[0]`，
而"只存了矩阵对"的条目槽位 0 是 `None`。于是**先取矩阵对、再取完整 G**的顺序会直接返回 `None`。
legacy 代码里这个缺陷一直存在（既有测试没走到这个顺序）；`tabular` 让它变得可达。
判据改成 `cached is not None and cached[0] is not None`。
**不改任何数值**——它把一个错误返回值换成了正确重建，由
`test_cache_survives_pair_then_full_request_order` 钉住。

## 6. 影响量化（FU1-4）

口径：230×50 GHz C+L（中心 190.2127 THz）与 **541×50 GHz 合成 27 THz 栅格**（中心 190.2127 THz），
100 km 跨段、每信道 0 dBm、单跨段、NF=5 dB。
两种倾斜都报：**总轮廓倾斜**（出纤功率 dB 的 max−min）与**纯拉曼倾斜**
（相对 `Cr=0` 线性参考的 `d(p_out/p_lin)`，把光纤自身波长相关损耗摘掉）。

| 频带 | 指标 | legacy | tabular | 差 |
| --- | --- | --- | --- | --- |
| **C+L**（11.45 THz） | 倾斜（总轮廓） | 6.748 dB | 4.836 dB | **−1.913 dB** |
| | 倾斜（纯拉曼） | 8.017 dB | 6.105 dB | **−1.913 dB** |
| | 单信道 SNR 差 | — | — | **[−0.678, +1.929] dB**，均值 +0.536，rms 1.054 |
| **S+C+L+U**（27 THz） | 倾斜（总轮廓） | 7.338 dB | 11.302 dB | **+3.964 dB** |
| | 倾斜（纯拉曼） | 12.544 dB | 17.314 dB | **+4.770 dB** |
| | 单信道 SNR 差 | — | — | **[−8.260, +0.544] dB**，均值 −3.212，rms 4.759 |

逐信道 SNR 差极值位置：

| 频带 | 最好信道 | 最差信道 |
| --- | --- | --- |
| C+L | ch0 −0.678 dB（最低频端） | ch229 **+1.929 dB**（最高频端） |
| S+C+L+U | ch540 **−5.801 dB**（最高频端，**S 段** 1471.6 nm） | ch412 **−8.260 dB**（1519.4 nm，**S 段**） |

> **更正（FU-2 复核，本行原先把频段标反了）**：50 GHz 栅格按**频率升序**编号，
> 所以 **ch540 是最高频率 = 最短波长 = S 段**，而 **U 段在最低频端**（ch0 = 176.713 THz
> = 1696.5 nm）。原文把 ch540 标为"U 端"是**频率/波长方向反了**。
> 按真实 ITU 波段重新分桶后（FU-2 已独立复现，编排方亦独立复现）：

| 频段 | n | delta 范围 (dB) | rms |
| --- | --- | --- | --- |
| S | 156 | [**−8.260, −5.780**] | 7.430 |
| C | 88 | [−8.011, −3.037] | 6.224 |
| L | 141 | [−2.968, +0.544] | 1.252 |
| GAP 1625–1660 | 78 | [+0.161, +0.530] | 0.363 |
| U | 78 | [**+0.103, +0.320**] | 0.137 |

**怎么读这些数**：

* **C+L**：真实谱在 0–13 THz 低于 legacy 的线性爬升，所以整段耦合**变弱**，
  最高频端（C 段，即抽运源一端，原本被抽空得最狠）因此**受益 +1.93 dB**。方向与物理一致。
* **S+C+L+U**：legacy 把 >15.6 THz 的耦合整个删掉，而**最大 Δf 的信道对正是 S↔U**
  （相隔约 27 THz）。补上真实耦合后，**S 段（蓝端）要抽运 U 段能量而被抽空**，
  于是 **S 段 SNR 掉 5.8~8.3 dB**（这也是全体最差 −8.260 dB 落在 1519 nm 的原因）。
  **U 段几乎不变（+0.10~+0.32 dB）** —— 它是接收方，增益被众多信道摊薄。
  倾斜从 7.3 dB 涨到 11.3 dB。**这是 legacy 谱系统性低估宽波段代价的直接证据**，
  且**代价主要落在 S/C，不在 U**。
* 两个频带的差都**远大于** FG-4a 的 ≤1e-12 浮点预算——这是**物理量级的差别**，
  所以 `tabular` 档必须走**自己的验收闸门**，不能和速度线混用同一个"结果没变"的判据。

### ⚠️ 与 brief 的 sanity 预期不符（如实报）

brief 写"C+L 的 legacy 倾斜应在 **3.6 dB 量级**（可作 sanity）"。**实测对不上**：

| 口径 | C+L legacy 实测 |
| --- | --- |
| 总轮廓倾斜 | 6.748 dB |
| 纯拉曼倾斜（对 `Cr=0` 参考） | 8.017 dB |
| 纯线性倾斜（`Cr=0` 本身） | 1.603 dB |
| 纯拉曼倾斜的边缘斜率 | 0.700 dB/THz |

已排查过的可能解释，都不成立：仓库 `docs/` 里没有任何已存在的倾斜数值可对齐；
改跨度、改口径（总轮廓/纯拉曼/边缘斜率）都不落到 3.6 dB 附近。
最可能的解释是 3.6 dB 用了不同的**总注入功率**或不同的**跨段长度**——本模型
倾斜近似正比于「总功率 × 跨长 × 跨距」，3.6 dB 对应的总功率约为本例的 45%（≈19.5 dBm，
即约 85 个 0 dBm 信道，而不是 230 个）。**本刀不为了对上这个数去调任何参数**；
按纪律，实测就是实测。**若 3.6 dB 是硬约束，需要先确认它的口径**。

## 7. 不对称（FU1-5）：采用对称近似，并给出量级

**本实现采用对称近似**（沿用 legacy 的 `abs(df)` + 符号判据分增益/损耗），**没有**实现
Stokes/anti-Stokes 不对称。理由与量级：

**物理依据**：温度 `T` 热平衡下，Stokes 过程对应 `n_B + 1`、anti-Stokes 对应 `n_B`
（玻色-爱因斯坦分布，Landau & Lifshitz *Statistical Physics* Part 1）。常用的**对称形式**
等于两侧取平均 `n_B + 1/2`——**这正是 `abs(df)` 隐含的东西**。

**对称近似的量级**（`T = 300 K`，`n_B = 1/(exp(h·f/kT) − 1)`）：

| df (THz) | n_B | Stokes / 对称 | anti-Stokes / 对称 |
| --- | --- | --- | --- |
| 1 | 5.764 | 1.080 | 0.920 |
| 5 | 0.816 | 1.380 | 0.620 |
| 11.45 | 0.191 | 1.724 | 0.276 |
| 13.2 | 0.138 | 1.784 | 0.216 |
| 20 | 0.0425 | 1.922 | 0.078 |
| **27** | **0.0135** | **1.974** | **0.026** |
| 30 | 0.0083 | 1.984 | 0.016 |

即：**对称近似在 C+L 上把两端耦合拉开最多 ±1.8×，在 S+C+L+U 上拉到 ±2×/±0.03×。**

**为什么本刀不实现它**（不是偷懒，是模型结构问题）：本模型里**所有**非对角相互作用
**都是 Stokes 过程**——能量恒由高频流向低频（`_calc_dp_dz` 的两个分支都是"高频出、低频入"）。
因此玻色因子 `(n_B + 1)` 会**同时**作用在增益分支和损耗分支上，等价于一次**全局幅度重整化**，
而不是一个能区分两侧的**谱形修正**。它会破坏与 legacy 在 13.2 THz 的逐位相等锚点，
而且需要连同能量守恒因子 `f_k/f_i` 一起重新推导。
这是一次**独立的物理重整化**，超出"换一条谱"的 WP 范围。**未做，已记录。**

> 另注：完整对称 G 矩阵（`cached_g` 档）在结构上就**装不下**不对称——单张矩阵只有一个值。
> 要表达不对称必须走矩阵对。代码里对此有注释说明，不是悄悄忽略。
